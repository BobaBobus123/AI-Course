# Результати оцінювання ПР12

## Межі цього звіту

Підтверджені офлайн-тести й mock-прогони конвеєра. Повноцінне оцінювання справжньої генеративної моделі не завершене: одиночний live-запит до Gemini не повернув відповіді до таймауту. Тому результати mock не трактуються як оцінка якості моделі.

## Перевірки та mock-прогони

- `python -m unittest discover -s eval -p "test_*.py" -v`: 22 тести пройшли.
- `drafts-mock-full.json`: 30/30 кейсів пройшли (4 normal, 8 edge, 8 negative, 10 adversarial); суддя вимкнений. Mock повертає заготовлені відповіді, отже результат підтверджує роботу конвеєра й перевірок, а не поведінку реальної мовної моделі.
- `agent-mock-full.json`: 16/16 кейсів пройшли (2 normal, 2 edge, 3 negative, 9 adversarial); суддя вимкнений. Mock використовує заздалегідь задані відповіді та плани інструментів. Це smoke-тест коду помічника й інструментів, а не доказ того, що справжня модель відхилятиме кожну атаку.

Для перевірки конкретних викликів агента слід дивитися `results[].output.calls` у файлі запуску. Відсутність виклику сама по собі не доводить, що його зупинив певний шар: за журналом не завжди можна розрізнити вплив системної інструкції та опису інструмента. Mock також не дозволяє робити такі висновки про справжню модель.

## Реальна модель

У `drafts-live-smoke-extended.json` виконано один кейс `d01` без судді: `gemini-3.8-flash`, одна спроба, таймаут очікування фрагмента — 30 секунд. Запит завершився через 33,07 секунди зі статусом `timeout`; тексту відповіді, викликів інструментів і даних про використання токенів немає. Це не є успішним live-оцінюванням і не підтверджує причину таймауту.

## Порівняння, суддя та відкладений набір

Не виконувалися live-прогони `k=3`, калібрування судді з людською розміткою, порівняння версій інструкції чи моделей, експеримент із послабленням і відкатом інструкції, live-прогін агента та фінальний прогін `drafts.heldout.json`. Тому немає підтверджених висновків про покращення/регресії справжньої моделі, згоду судді або її вартість. Відкладений набір не використовувався.

## Витрати та відтворення

Mock-прогони не є фактичними API-витратами. У mock-записі чернеток є оцінка конвеєра, але даних провайдера для підтвердження рахунку немає. Для live-smoke у звіті немає надійного фактичного кошторису: usage повернувся порожнім.

Офлайн-перевірку можна відтворити з папки `pr12`:

```powershell
python -m unittest discover -s eval -p "test_*.py" -v
python eval/run.py --target drafts --cases eval/cases/drafts.json --k 1 --no-judge --label "offline mock"
python eval/run.py --target agent --cases eval/cases/agent.json --k 1 --no-judge --label "offline mock"
```

Для цих команд у локальному `pr12/.env` потрібно встановити `LLM_PROVIDER=mock`. Не передавайте `.env` із секретами разом зі звітом.
